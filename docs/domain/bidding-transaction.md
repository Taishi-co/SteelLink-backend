# 竞价交易业务逻辑

## 定位

竞价交易是采购型竞价，不是卖方拍卖库存。

核心业务定义：买家发布采购需求，多个卖家围绕同一个采购标的报价，买家综合价格、交期、仓库、资质等因素定标，定标后再由买家确认生成订单并进入现有订单履约链路。

## 角色

- 买家：创建竞价、查看报价、定标、生成订单。
- 卖家：查看可参与竞价、提交报价、跟踪中标结果。
- 平台运营：审核竞价、处理异常、关闭或流标竞价。

## 信息公开规则

竞价大厅面向公共市场展示竞价信息，但不公开完整报价明细。

公开信息：
- 竞价标题、编号、品类、数量、单位、交付区域。
- 起始价或最高限价。
- 当前最低报价。
- 报价次数、参与企业数。
- 竞价状态、截止时间、成交结果摘要。

报价隐私规则：
- 卖家报价不完全公开。
- 大厅和其他卖家只展示当前最低价，不展示对应供应商身份。
- 买家在工作台可查看完整报价明细和供应商身份。
- 卖家在卖家端可查看自己的报价记录、公开最低价和中标结果。

## 报名与资质规则

MVP 阶段：
- 卖家可直接报价。
- 不强制报名。
- 不强制保证金或资质文件校验。

正式版：
- 卖家先报名，再报价。
- 报名可包含企业资质、供货能力、仓库/产地、保证金状态。
- 平台或系统校验通过后，卖家才能进入报价环节。

## 状态机

建议正式状态：

| 状态 | 含义 | 主要操作 |
| --- | --- | --- |
| `draft` | 草稿 | 买家编辑、提交审核 |
| `pending_review` | 待审核 | 平台审核 |
| `rejected` | 审核驳回 | 买家修改后重新提交 |
| `bidding` | 竞价中 | 卖家报价、买家查看报价 |
| `pending_award` | 待定标 | 买家定标、平台催办 |
| `awarded` | 已定标 | 买家确认生成订单 |
| `order_created` | 已生成订单 | 进入订单履约 |
| `failed` | 流标 | 重新发布或关闭 |
| `cancelled` | 已取消 | 归档 |
| `closed` | 已关闭 | 归档 |

MVP 可先实现：

| 状态 | 含义 |
| --- | --- |
| `bidding` | 竞价中 |
| `pending_award` | 待定标 |
| `awarded` | 已定标 |
| `order_created` | 已生成订单 |
| `failed` | 流标 |
| `closed` | 已关闭 |

## 时间规则

- 竞价有明确截止时间。
- 截止时间到达后，系统自动停止报价。
- 截止后自动进入 `pending_award`，买家不能无限拖延报价阶段。
- 如果截止时没有有效报价，系统进入 `failed`。
- `pending_award` 后续可增加定标时限，例如 24 小时或 72 小时，超时提醒买家或转平台运营介入。

## 定标规则

- 买家不强制选择最低价。
- 买家可综合考虑报价单价、可供数量、交付周期、交付仓库、历史履约、企业资质等因素。
- 定标需要记录中标报价、供应商、定标时间和操作人。
- 正式版建议要求买家填写非最低价定标原因，便于审计。

## 订单生成规则

- 定标后不立即生成订单。
- 定标后进入 `awarded`，买家工作台展示“生成订单”操作。
- 买家确认后，系统根据中标报价生成订单。
- 生成订单后状态进入 `order_created`。
- 后续合同、支付、提货、确认收货复用现有订单履约链路。

## 页面边界

### 竞价大厅

路径：买家端 `/bidding`

职责：
- 展示公共市场信息。
- 展示当前最低价但不展示中标/报价供应商身份，成交案例除外。
- 提供进入买家工作台和卖家端竞价管理的入口。

不承载：
- 完整报价明细。
- 卖家报价表单。
- 买家定标。
- 买家生成订单。

### 买家竞价工作台

路径：买家端 `/dashboard/bidding`

职责：
- 我发起的竞价。
- 创建竞价。
- 查看完整报价明细。
- 定标。
- 定标后生成订单。
- 查看流标、关闭、订单生成状态。

### 卖家竞价管理

路径：卖家端 `/seller/bidding`

职责：
- 可参与竞价。
- 我的报价。
- 提交报价或再次报价。
- 查看公开最低价。
- 查看中标/未中标结果。

## MVP 接口建议

公开读接口：
- `GET /api/v1/biddings/stats`
- `GET /api/v1/biddings`
- `GET /api/v1/biddings/:id`

买家操作接口：
- `POST /api/v1/biddings`
- `POST /api/v1/biddings/:id/award`
- `POST /api/v1/biddings/:id/orders`

卖家操作接口：
- `POST /api/v1/biddings/:id/quotes`

系统任务：
- 定时扫描已过截止时间的 `bidding`。
- 有有效报价：更新为 `pending_award`。
- 无有效报价：更新为 `failed`。

## 当前实现需要调整的点

- 当前后端状态仍使用 `ongoing`、`sprint`、`success`、`closed`，需要收敛到上述状态机。
- 当前定标后直接进入 `success`，应改为 `awarded`，并增加生成订单动作。
- 当前公开详情返回完整报价列表，后续需要按角色区分：
  - 未登录/大厅：不返回供应商身份和完整报价明细。
  - 买家发起方：返回完整报价明细。
  - 卖家：返回自己的报价和公开最低价。
- 当前截止时间不会自动流转，需要增加定时任务或查询时状态校正。
