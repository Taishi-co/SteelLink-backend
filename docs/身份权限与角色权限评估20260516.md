# 身份权限与角色权限评估 20260516

## 结论

当前系统已经具备身份分层、企业认证、供应链角色和服务能力权限的基础闭环，可以支撑“未实名个人 / 实名个人 / 企业”三层身份，以及“采购商、供应商、仓储方、物流方、资金方”五类企业角色。

企业认证时填写供应链角色，后端会映射到对应平台服务能力：

| 供应链角色 | 后端企业角色 | 自动开通能力 |
| --- | --- | --- |
| 采购商 | `buyer` | `procurement` |
| 供应商 | `seller` | `sales` |
| 仓储方 | `warehouse` | `warehouse` |
| 物流方 | `logistics` | `logistics` |
| 资金方 | `fund` | `finance` |

企业审核通过后，用户角色会从个人变为企业，初始服务申请同步通过，对应服务权限进入已开通状态。后端接口已经使用 `RequireEnterpriseService` / `RequireTradeCapability` / `RequireProviderService` 做服务能力拦截。

## 身份分层

### 未实名个人

已支持。未实名个人可以浏览商城公开信息，登录后个人工作台只展示个人工作台、站内信、实名认证、企业认证等基础入口。创建企业时后端强制要求先完成实名认证。

### 实名个人

已支持，但当前业务权限与未实名个人差异较小。建议保留“实名个人”作为企业认证、加入企业、提交高风险申请的前置门槛，不单独开放交易能力。后续可以增加这些差异：

- 允许实名个人收藏、询价、保存采购需求草稿。
- 允许实名个人申请加入企业或创建企业。
- 不允许实名个人下单、上架商品、申请金融服务、发起物流履约。

### 企业

已支持。企业认证通过后，系统会基于供应链角色自动开通对应服务能力。企业也可以通过服务入口继续申请其他服务能力，平台审核通过后追加权限。

## 角色权限落地情况

### 买家权限

大部分已支持。买家能力对应 `procurement`，可访问钢材行情、竞价管理、订单、资金服务、仓库/货物管理、物流服务和服务入口。资金服务目前主要是查看金融商品，并在订单支付节点申请融资。物流转运已有前端入口和基础委托接口，可先作为轻量能力保留。

已补齐：买家可以查看自己作为货主的出入库记录，并提交仓储托管需求。

### 卖家权限

大部分已支持。卖家能力对应 `sales`，可使用卖家中心的数据概览、商品管理、参与竞价、订单管理、履约核销、站内信、店铺设置。卖家在买方/企业工作台也可以查看资金、仓储、物流等交易辅助服务。

已补齐：销售企业可以提交仓储托管需求、查看自己作为货主的出入库记录。卖家中心不再默认向销售企业展示“仓库管理/上架仓库”入口，避免和“卖家不能上架仓库”的规则冲突。

### 仓储方权限

部分已支持。仓储方能力对应 `warehouse`，可上架仓储资源，处理仓库确认、入出库记录和物流到仓后的单据协同。当前系统已具备仓储资源、仓库确认、出入库作业、履约单据上传等基础模型。

后续缺口：如果要对接仓储 MRP，需要补更细的库存台账、库位、批次、质检、质押冻结、WMS/MRP 同步状态。

### 物流方权限

部分已支持。物流方能力对应 `logistics`，可上架运力资源、参与物流竞价、承接物流委托、推进物流节点、上传司机/车辆/单据/GPS 等履约信息。

后续缺口：司机管理目前偏轻量，需要独立司机档案、车辆档案、证照有效期、司机车辆绑定和审核。

### 资金方权限

部分已支持。资金方能力对应 `finance`，可上架金融产品，处理融资申请、风控、债务合同、手续费、分佣、放款、货权质押和释放。

后续缺口：资金方的货权监控可以继续增强，包括监管仓库存快照、物流在途异常、质押物估值、预警和放款后贷后管理。

## 平台仓库与自填仓库

你的判断是正确的：买家下单或卖家上架商品时，如果选择的是平台已审核仓储方上架的仓库，平台才能做仓库确认、库容协同、出入库单据、货权监控和资金方监管仓闭环。

如果是自填地址或线下仓库，系统只能把它作为收发货地址使用，不能可靠管理库容、单据和货权状态。因此前端需要明确警示。

当前系统已有警示：

- 买家结算页已提示平台仓库与自填仓库的管理差异。
- 卖家商品发布页已提示平台登记仓库与手动填写仓库的管理差异。
- 买卖方货物管理页已提示非平台仓库无法进行平台级货权监控。

## 本轮开发内容

1. 后端允许采购商和供应商提交仓储托管需求。
2. 后端允许采购商、供应商、仓储方查看仓储作业记录，并按货主或仓储方身份过滤。
3. 前端企业工作台侧边栏增加服务商直接入口：仓库管理、运力资源管理、金融产品管理。
4. 卖家中心菜单按服务能力显示，销售企业不再默认显示仓库上架入口。

## 后续开发建议

1. 把企业角色从单选扩展为多能力组合时，继续以服务权限表为准，不要只依赖 `enterprise_role`。
2. 为实名个人增加“可创建企业 / 可加入企业 / 可保存询价草稿”的轻量差异，不建议开放交易闭环。
3. 仓储方补 MRP/WMS 对接抽象：库存快照、库位、批次、质押冻结、单据回传。
4. 物流方补司机和车辆主数据，和物流单据上传节点打通。
5. 资金方补货权监控看板，汇总监管仓、物流、收货确认和质押释放。
