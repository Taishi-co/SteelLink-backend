# Test Cases

## 测试范围

- Feature ID: `SL-BE-GROUP-PROCUREMENT-BIDDING-V2`
- 测试负责人: Codex

## Happy Path

| 编号 | 场景 | 前置条件 | 步骤 | 期望结果 |
| --- | --- | --- | --- | --- |
| TC-01 | 创建竞价项目 | 已存在 2 条待处理集采申请与 1 个管理端账号 | 调用创建项目接口并关联申请 | 返回项目详情，状态为 `collecting/quoting`，申请被关联 |
| TC-02 | 邀请并审核供应商 | 已存在项目、2 个卖家企业 | 管理端邀请卖家并审核通过 | 供应商报名状态更新为 `approved` |
| TC-03 | 卖家提交报价 | 卖家已审核通过，项目未截止 | 卖家提交价格、数量、交期、仓库信息 | 返回报价详情，项目可查询到该报价 |
| TC-04 | 卖家更新报价 | 卖家已有历史报价，项目未截止 | 再次提交报价 | 保留最新生效报价，历史状态按设计更新 |
| TC-05 | 管理端定标 | 项目下至少存在 2 个有效报价 | 管理端选择一个报价定标 | 项目状态变为 `awarded`，中标结果可查询 |
| TC-06 | 基于中标报价成单 | 项目已定标且中标报价绑定商品资源 | 管理端执行成单 | 生成真实订单，项目状态变为 `order_created` |

## Exception Path

| 编号 | 场景 | 前置条件 | 步骤 | 期望结果 |
| --- | --- | --- | --- | --- |
| TC-EX-01 | 未审核通过卖家报价 | 卖家报名状态非 `approved` | 提交报价 | 返回无权报价或状态错误 |
| TC-EX-02 | 截止后报价 | 项目已超过报价截止时间 | 提交报价 | 返回项目已截止 |
| TC-EX-03 | 重复定标 | 项目已定标 | 再次执行定标 | 返回当前状态不可定标 |
| TC-EX-04 | 无中标结果成单 | 项目未定标 | 执行成单 | 返回先完成定标 |
| TC-EX-05 | 中标商品库存不足 | 中标报价对应商品库存不足 | 执行成单 | 返回库存不足，项目状态不变 |
