# Test Cases

## 功能测试

### Test Case 1: 直采支付 - 商品已有货权凭证
**前置条件:**
- 有一个待支付订单
- 订单商品已上传货权凭证

**步骤:**
1. 调用直采支付接口，不传`title_voucher_url`
2. 验证支付成功
3. 验证订单记录了商品的货权凭证

**预期结果:**
- 支付成功
- 订单使用了商品的货权凭证

### Test Case 2: 直采支付 - 支付时上传货权凭证
**前置条件:**
- 有一个待支付订单
- 订单商品没有货权凭证

**步骤:**
1. 调用直采支付接口，传入`title_voucher_url`和`title_voucher_remark`
2. 验证支付成功
3. 验证订单记录了上传的货权凭证

**预期结果:**
- 支付成功
- 订单使用了上传的货权凭证

### Test Case 3: 直采支付 - 两者都有时优先使用上传的
**前置条件:**
- 有一个待支付订单
- 订单商品已上传货权凭证

**步骤:**
1. 调用直采支付接口，传入`title_voucher_url`和`title_voucher_remark`（与商品不同）
2. 验证支付成功
3. 验证订单记录了上传的货权凭证（而非商品的）

**预期结果:**
- 支付成功
- 订单优先使用了上传的货权凭证

### Test Case 4: 上传支付凭证 - 无预加载错误
**前置条件:**
- 有一个待支付订单

**步骤:**
1. 调用上传支付凭证接口
2. 验证返回成功

**预期结果:**
- 上传成功
- 没有"预加载订单项失败"错误

### Test Case 5: 错误信息详细性
**前置条件:**
- 有一个待支付订单
- 模拟数据库错误场景

**步骤:**
1. 调用直采支付接口
2. 验证错误信息包含具体原因

**预期结果:**
- 错误信息包含具体的错误原因（如"查询订单失败"、"保存订单失败"等）
